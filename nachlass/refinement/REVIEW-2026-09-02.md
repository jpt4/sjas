## Summary (final)

The commit's 22 claimed corrections were checked against page images,
`registry/results.md`, extraction records, and independent recomputation. The
overwhelming majority hold up: the Hybrid(H) arithmetic, the condition-(2)
identification, the Beklemishev–Shamkanov p.8/p.14 substance, the Pakhomov

Beklemishev–Shamkanov p.14 quote (in R2 and R3, both tagged "image-verified")

stronger guarantee ("every mathematical quotation image-verified") than the
documents and machinery actually deliver (T3-5). Several smaller citation/

### TIER 1 — audit-r.sh machinery defects (found by constructing test cases in an isolated scratch copy; no repo file was modified — see Method notes for the harness)

**T1-C. R-B's mathematics-detection regex omits the two most dangerous named corruption symbols (`℧→0`, `ℑ→=`), and also omits floor/ceiling/tower notation the corpus's own drift ledger (D71) documents as silently destroyed.**
`audit-r.sh`'s `run_r_b` flags a `txt`-tagged row only if it matches
`[□⌜⌝♯⊢≥≤∧⊃¬∀∃⊠⊤⊥]`. Constructed test: injected a `txt`-tagged register row
containing `℧(x)` (a stand-in for `Willard2005`'s U-Height/tangibility notation)
and a second row containing `ℑ(H) = Σ χ(p_i)` (the *exact* quote already present
elsewhere in this same VERIFICATION.md, correctly tagged `img`) into an isolated
copy of the register; `run_all_r` reported **`R-B: 26 register rows well-formed;
no txt row carries mathematics`** for both — i.e., it does not detect either.
This matters specifically because the task's own tooling-hazard warning (and
this repo's drift **D71**, `registry/notation.md`, `extraction/willard2006b.md`)
names exactly these silent-substitution corruptions (`℧`→digit `0`, Fraktur
`ℑ`→`=`, floor/ceiling/tower collapse) as the dangerous class — more dangerous
than a stripped `□` because the output looks like valid, unremarkable text
rather than an obvious gap. R-B's regex protects against the *box-stripping*
failure mode this commit's narrative foregrounds but not the *substitution*
failure modes the task briefing and the codebase's own drift ledger call out.
Reproduction: isolated copy of `nachlass/{codification,refinement}` plus the
top-level `lit/` (symlinked), `err`/`FAIL` stubbed, `. ./audit-r.sh; run_all_r`
after inserting the two rows above into a copy of `VERIFICATION.md`.

**T1-D. R-D's "adjacent withdrawal marker" guard is defeated by a coincidental guard word in neighboring, unrelated prose — the exact bug class the script's own comment says was already found and fixed once, only narrowed, not closed.**
`run_r_d`'s window is `grep -C1` (one line of context each side) grouped into
blocks by `--` separators; a block counts as *guarded* if it contains **any**
of a fixed list of words (`withdrawn|retracted|corrected|superseded|earlier|
first draft|no longer|claimed|That draft|that draft`) anywhere in the block,
with no check that the guard word is actually about the same claim. Constructed
test, in the isolated copy: appended to `R2-beklemishev-shamkanov-assessment.md`
—
```
The encoding convention used earlier in this document was later withdrawn.
Indeed H_<w proves the existence of every hereditarily finite set, which is what matters.
That is unrelated to the encoding point above.
```
— three lines, where line 1's "withdrawn" is about an unrelated encoding
convention and line 2 verbatim reasserts the retracted Pakhomov claim (pattern
1 in `run_r_d`'s list) with no withdrawal language of its own. Result:
**`R-D: 5 retracted claims checked; each occurrence carries an adjacent
withdrawal marker`** — a false pass; `FAIL=0`. Control test confirms the
mechanism: the *same* reassertion with no guard word anywhere nearby correctly
produces `AUDIT-FAIL: R-D: retracted claim 'Pakhomov H_<w proves successor
totality' appears 1 time(s) without an adjacent withdrawal marker`. So R-D
does catch a bare, unguarded, verbatim reassertion — the exact scenario its
in-file comment says was the reason the window was narrowed from "elsewhere in
the section" to `-C1` — but narrowing the window only raised the bar for the
same failure mode (the guard word must now be within a line rather than
anywhere in the section) rather than fixing its cause (no check that the guard
word and the claim are about the same thing). Given how densely this stage's
own documents discuss withdrawals in close proximity (by design — see Rule 4),
a future paraphrase-and-partial-retraction sitting one line from an unrelated
"corrected"/"earlier" is a realistic way for this to misfire again.

**T1-E (related, lower severity). R-D matches literal strings, not the claims they name — any rewording of a reintroduced defect evades it entirely.**
Constructed test: reasserted the Pakhomov claim in different words ("Pakhomov's
`H_<w` proves successor totality after all, so R1 is falsified") with no guard
word nearby. `run_all_r` reported **no** R-D failure, because neither of the
two substrings in that pattern's row (`proves the existence of every
hereditarily finite set` / used only as the *label*, not matched — the actual
matched pattern is the *first* tab-separated field) appears verbatim. R-D is
therefore a regression guard against the *exact sentences* this review
happened to retract, not a semantic check that the underlying claims stay
retracted — its name ("stale-retraction check") promises more than a
fixed-string grep can deliver. This is a scope limitation inherent to the
chosen mechanism, not a bug exactly, but it means R-D's protection decays to
near-zero the moment anyone edits the surrounding prose, which is the normal
way documents evolve.

**Checked and not defective:** R-A (nonexistent paper key `Willard2099`

### TIER 2 — Unsupported / overclaimed (or under-claimed)

**T2-A. Item 7 — the Hybrid(H) withdrawal argument is sound but its positive replacement ("most plausibly the cost side") is under-explained; it does not, however, "prove too much."**
Checked whether R3 §3.1's "♯ is model-theoretic, naming axioms are true hence
Good(∞), so they cannot lower ♯(β)" argument would equally undercut the other
four dials' cost-side placement. It does not: the argument only rules out ONE
mechanism (true axioms directly lowering the envelope); it says nothing about
`Log(q_β)`, so it is fully compatible with `ℜ`/`Herb−k` (which touch the proof
*apparatus*, not the axiom set, so the argument doesn't even apply), `Z` (whose
added axioms — LEM instances `Υ∨¬Υ` — are also unconditionally true, so by the
same logic they too cannot lower `♯`, consistent with `Z` being placed on the
cost side rather than contradicting it), and Level(n) (whose Group-3 axiom is
part of `B^ξ`, i.e., a different mechanism again). So no collapse. The
argument is in fact *better* supported than R3 states: `Willard2011#Lem6.1`
(`full` status, per `registry/results.md`) proves "Adding true `Π^ξ₁` sentences
to the base preserves each stability property" — a directly on-point, citable
result for exactly the claim R3 makes about truth and Good(∞)/stability, which
R3 does not cite here. The real gap is the other direction: R3's positive
replacement claim ("most plausibly by changing which `β⊃B^ξ` are inconsistent
and how cheaply") is not actually explained — it is not obvious how adding
axioms that are individually true and individually harmless to the envelope
could change which extensions are inconsistent at all, and R3 does not supply
a mechanism, leaving `Log₂C_n`'s connection to `Log(q_β)` genuinely open. This
is honestly flagged ("which term it moves is not established here") rather
than asserted, so it is Tier 2 (incomplete, honestly labeled), not Tier 1.

**T2-B. Item 8 — the Level(n) "Group-3 axiom, hence base, hence cheaper 0=1" mechanism is coherent and its scaffolding is corpus-supported, but the causal step itself is conjecture, correctly labeled as such.**
Checked `codified-sjas.md` §5.1-5.2 (lines 563-579): confirms Group-3 is "part
of `B^ξ`" and that Level(n) is *exactly* "what Group-3 quantifies over" / "what
Group-3 asserts" (§5.2's table literally rows Level(n) against "what Group-3
quantifies over"), so R3's framing ("Level(n) fixes what the Group-3 axiom
asserts, and Group-3 is part of `B^ξ`") is directly grounded in the corpus,
not invented. Checked `extraction/willard2004.md` §3 (the Level hierarchy) and
its quoted "all definitions of consistency... are equivalent... under strong
enough models" passage: this is model-theoretic equivalence, not a proof-length
statement, so R3's own admission that this quote does NOT support the "cheaper
to derive" step is correct and appropriately self-critical. The remaining
causal claim — that a logically *stronger* false self-referential axiom yields
a *shorter* refutation — is a plausibility argument (a stronger, more
encompassing false premise is "more useful" as a lever), internally coherent
and not self-contradictory (unlike the draft it replaces, which conflated "what
counts as a refutation" with "cost", a real category error the new text avoids
since `q_β` stays fixed at proofs of `0=1` per Def. 4.5 — confirmed at
`R3-the-margin.md` §1.1's explicit reading of Def. 4.5). But it is not derived
from any cited theorem, and R3 says so explicitly ("this Refinement's reading,
and it is the least well-supported of the five"). This is a correctly-labeled
conjecture, not a defect — Tier 2, not Tier 1.

**V1. Item 1 — Hybrid(H) recurrence and arithmetic (refined-sjas.md §5, R3 §3.1, VERIFICATION.md Computed claims).**
Page image `willard2006a_p30-30.png` confirms the recurrence verbatim:
"Hybrid(H) refer to a naming convention that defines C_i to equal
⌈2^([Log(i)]^H)⌉ · C_{i−1}" for fixed H and i≥3, and confirms "Theorem 3's
partial exception to the Second Incompleteness Theorem remains valid when one
sets H=1... by choosing a constant H>1, the second incompleteness effects
under Theorems 4 and 4* can be generalized" and that the paper itself calls
this "midway between the additive and multiplicative conventions" — the loose
gloss the documents say an earlier draft over-relied on.
Recomputed independently: Log₂C_n = Σ_{i≤n} Log(i)^H ≈ log₂(n!) for H=1, and by
Stirling log₂(n!) = n log₂n − n log₂e + O(log n) = Θ(n log n). Numerically:
n=10 → 21.79 bits, n=100 → 524.76, n=1000 → 8529.4 — I recomputed these three
independently via log10(n!) (Stirling / known values) and they match
