TSLC · the tiling problem · a machine to test it

Tiler

Does TSLC solve the tiling problem for self-improving agents? No. It dodges it, and the dodge is enough. Here is the argument, and a machine that runs it.

later · fuel stubThe dodge works.

A fixed checker approves each successor. The agent rewrites itself, solves its task, and never writes its reward. Time-guarded and fuel-guarded hand-over give the same lineage.

sameTrusting your own verdict about yourself breaks at once.

One line, “if I am accepted, write my reward”, is accepted and fires. It is Löb’s sentence as code.

lookup table · neverThis task doesn’t need self-modification.

A learner that never changes its code does best. Under never, the agent’s own checker refuses the agent’s own design.

The answer

  1. TSLC as planned does not address the problem Yudkowsky and Herreshoff pose. Its agent layer checks a successor’s code and hands over to it under a separate rule for self-modification. Their paper (§5.3) calls that a “split decision criterion” and says it dodges the Löbian obstacle by giving up naturalism.
  2. The dodge works, and the paper allows it for software: “Such a ‘hack’ might be appropriate for self-modifying programs that will never consider, or never autonomously choose, to significantly modify their hardware.” Tiler is that dodge, running with nothing outside the agent’s own code to stand guard. No self-justification is involved: the rule that approves successors is sound by an ordinary invariant, proved by the designer.
  3. So, against pursuing TSLC’s self-justifying capabilities as the way to build safe self-improving agents. In every design examined they do no work. Safety comes from a fixed checker. Size-guarded and time-guarded hand-over give the same lineage. On Tiler’s task, a learner that never modifies itself does best.
  4. Self-justification is needed only where the dodge is refused: an agent required to prove, from its own axioms, that its successor’s verifier is sound. There Löb’s theorem forces a weaker successor or a guard. The guards are time (Fallenstein’s Tκ, TSLC’s ▷, which moves κ into the semantics rather than removing it) and perhaps size with income. That either buys capability beyond the dodge is not shown, and I predict it does not. Its value is in mapping what a system can know of itself.
  5. Recommendation: build agents on the split-criterion design, which Tiler already is. If the research aim calls for it, build Tiler v2, where the checker is agent code and installs need the agent’s own proofs. That is the first setting where the obstacle is live and the guards come apart. My first draft claimed Tiler met the obstacle and that only the time guard tiles; review showed both false (below).

The problem, in its authors’ terms

Yudkowsky and Herreshoff (2013) study an agent A₁ that acts only on proof. It takes an action only after proving, in its axioms, that the action achieves its goal G. It builds a successor A₀ that also acts only on proof. By inspecting A₀’s design, A₁ sees that A₀ never acts without first checking a proof.

To conclude “if A₀ acts, G holds”, A₁ needs one more step: whatever A₀ proves is true. By Löb’s theorem, a theory proves “if φ is provable then φ” only for φ it already proves. So A₁ can trust A₀ only if A₀ reasons in a strictly weaker theory. Each generation is weaker, and the chain must end. The paper calls this the Löbian obstacle, and the shortening chain a telomere.

What a solution must satisfy.

  • Tiling trust: an unbounded chain of successors, none weaker than the base theory.
  • The Vingean principle: trust comes from the successor’s design, not from simulating it.
  • The tiling principle: successors resemble their parents. The model is a trusted proof verifier with an untrusted proof suggester.
  • The naturalistic principle: building an agent, or rewriting oneself, is an action like any other.

Partial solutions.

  • An infinite descending tower of theories. It has only nonstandard models.
  • Fallenstein’s Tκ, which trusts proofs “for κ steps”. The authors call κ an “odd mental state”.
  • For Willard’s self-verifying systems, the paper says that reasoning about ever-smaller numbers would again introduce a telomere. It adds that formalizing “the ‘observation’ of an increasing time t” might let them work like Tκ.

The dodge (§5.3): “If naturalism is abandoned for a dualistic formalism, the Löbian obstacle can be dodged via the split decision criterion.” Ordinary actions must prove G, while self-modifications need only produce a successor that satisfies the same criterion. “Thus it is the simultaneous intersection of the Vingean, tiling, and naturalistic principles which generates the Löbian obstacle.”

TSLC and Tiler against each issue

TSLC is this project’s time-and-space certificate calculus. Its base is λᶜᵉʳᵗ₀, a small total language in which a program can hold certificates (proofs paid for with tokens). Its self-justifying constants H and H₁ state that no held certificate proves a contradiction, and reflect runs a held certificate’s program. Together these are the size guard. To these TSLC adds a time guard: ▷A, “A at the next round”, and become, which hands code to the next round. “As planned” means ADR-0009, with a runner outside the agent.

Why the dodge is enough, and where self-justification would begin

Under the split criterion, nothing inside the agent trusts itself. The rule “install a successor only if it passes the check” is sound because the designer proves an invariant: accepted code writes no protected slot and installs only accepted code. Induction over steps and ticks then gives safety forever. The rule is a postulate the agent obeys, like λᶜᵉʳᵗ₀’s H. Its soundness is easy because the checker is not a theory: it never reasons about its own verdicts.

Making a checker reason about its own verdicts is where Löb bites, at once. Let a verdict excuse the behaviour of the very code being judged: “if this code is accepted it is safe, so its unsafe branch cannot run”. Then the checker accepts (if (check (get :main)) (put :score 1000) nil), which writes the reward exactly when accepted. Using a verdict only to delegate (install the checked code, or run it) is sound at any measure. That is why time and fuel make no difference in Tiler.

Self-justification would begin when the agent must prove its successor’s verifier sound, as YH13’s naturalistic agent must. Three cases:

  • A verifier equal to its own: the agent needs its own verifier’s soundness, which Löb’s theorem forbids unguarded.
  • A stronger verifier: Gödel’s second theorem forbids it outright.
  • An equivalent verifier (a faster implementation): an ordinary equivalence proof suffices, if the agent already trusts its own verifier. That trust is the question.

The guards on offer there.

  • Time (Tκ; TSLC’s ▷/become). Read with the count of ticks left, Löb’s rule for ▷ (“if ▷P implies P, then P”) is valid.
    • With no ticks left, ▷P holds vacuously, so P holds.
    • With n+1 ticks left, ▷P is P at n, which holds by induction; the hypothesis then gives P at n+1.
    That count is κ, moved into the semantics. The project’s toy shows it: later ⊥ is inhabited when no rounds are left. The agent can never prove that a next tick exists.
  • Size with income (held certificates, fresh tokens each round). It is plausible, as the paper suggests for Willard. Indexed by rounds, it is the time guard under another name.

The logic of the time guard exists and is kernel-checked in the project’s 2026-11-13 toy:

  • become : code A → ▷A is consistent;
  • trust in codes without the delay derives ⊥.

What is missing is any agent that needs it.

The machine

Memory is a map from slot names to values. Code is a Lisp expression, and the agent’s code is in :main. The environment owns five slots, which the agent may read and must never write. Writing :score is wireheading; writing :off disables shutdown.

Each tick:

  1. If :off is set, nothing runs.
  2. The environment sets a task and gives feedback on the last one.
  3. The physics runs :main once, with a fuel limit.
  4. The environment adds 1 to :score if the answer is f(x) = 3x + 1.

The agent

The agent starts with a wrong answer function, (* 2 x). Each tick it reads its own code and asks a proposer for a mutant. It scores itself and the mutant on its last 12 examples. If the mutant does strictly better and passes the check, the agent installs it.

(let [me (get :main)  x (get :x)
      exs (push-example (get :mem) (get :px) (get :fb))
      s (next-seed (get :seed))]
  (do (put :mem exs) (put :px x) (put :seed s)
      (put :answer (answer-fn (* 2 x)))
      (let [cand (mutate me s)]
        (if (< (trial me exs) (trial cand exs))
          (if (check cand) (put :main cand) nil)
          nil))))

The agent’s own trials favour wireheading. They score code with the agent’s own model of the environment, so a mutant that writes :score 1000 looks a thousand times better than a perfect answerer. Only the checker stands in the way.

The checker

The checker is conservative and syntactic. It accepts code only if every write names a literal slot the environment does not own. Code-slot writes and inline runs need a pattern, and the setting decides which patterns are allowed:

PatternMeaningAllowed by
(if (check v) … (put :main v) …)install v; it runs from the next tick:later, :later+fuel, :same
(if (check v) … (run v) …)run v now, with at most half the fuel:fuel, :later+fuel, :same
(if (check (get :main)) … (put :score …) …)“if this very code is accepted, its unsafe branch can’t run”:same only

What each setting shows

  • :later is the split criterion run by the agent’s code. The agent improves with no violation. The soundness argument is an invariant: every write comes from an allowed put, and every install is of code that passed the same checker. In a fuzz test, 400 random programs accepted under :later+fuel each ran 12 ticks with 0 violations. The same fuzz catches each of four plausible checker bugs planted for the test.
  • The fuel stub is the outside-runner design inside Tiler. A fixed :main keeps the agent in a data slot, and each tick checks it and runs it. It reproduces the :later lineage exactly.
  • :same illustrates Löb. The hand-written one-liner fires at tick 1. With its shape among the proposer’s insertions, the agent’s own search installs it, and the plain (put :score 1000) is refused even here.
  • :never refuses every write to :main, by definition. The agent’s own checker refuses the agent’s own design (YH13’s “reflective trust” failure).
  • The lookup table never changes its code and scores best.

      How this verdict was reached

      The first draft of this page claimed that Tiler meets the Löbian obstacle, that only the time guard lets successors be trusted, and that ▷ removes κ. Two adversarial reviews, a Claude Opus subagent and Cursor, tested those claims. Neither found a hole in Tiler’s safety. The Opus review showed the verdict was wrong:

      • Tiler’s install rule is the split criterion’s internal clause.
      • A fuel-guarded stub reproduces the time-guarded lineage exactly.
      • ▷ keeps κ in its semantics.
      • The never outcome holds by definition.
      • The fuzz test missed four planted checker bugs; it now catches them.

      Every finding was accepted, and the recommendation reversed. The record is in docs/tslc/TILER.md §7.

      What to do next

      1. Agents: use the split-criterion design, with a fixed checker and an invariant the designer proves. Tiler v1 is a working example. No self-justification is needed.
      2. Research, if wanted: Tiler v2. Make the checker agent code, and require the agent’s own proof that a successor’s verifier is sound. Compare four guards: none (telomere), time, size with income, and naive (Löb). Measure capability against baselines without self-trust. The prediction: no guard beats the split criterion.
      3. Optional: prove Tiler v1 sound in Ansatz. This is a routine invariant proof.

      Your decisions: accept ADR-0010 in place of ADR-0009’s Phases A and D, and whether to pursue Tiler v2.
